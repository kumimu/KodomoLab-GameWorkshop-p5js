# 90分進行実装チェックリスト

**目的：** コーチが90分ワークショップを実際に進行する時に、各フェーズで確認すべき項目をチェックリスト化。

## ⚠️ トラブルシューティング

### 時間が押している場合

#### 0:50 時点で段階1が未完了の場合
```
対応方法：
- 「段階2に進みます」とアナウンス
- 未完了の生徒に「後で完成させるので大丈夫」と伝える
- コーチが個別サポートして急ぎ完成させる
```

#### 1:10 時点で段階2が未完了の場合
```
対応方法：
- 段階3はスキップ
- 段階2の完成に注力
- テスト・デバッグの時間を 15分 に短縮
- 発表を 5分 に短縮
```

#### 1:30 時点でテスト準備ができていない場合
```
対応方法：
- テスト・デバッグの時間を 5分 に短縮
- 発表準備を簡略化
- 発表は 2-3 生徒に限定
```

### 生徒が早く完成している場合

#### 段階2を 0:40 に完成した場合
```
対応方法：
- 「段階3へ進んでいいですよ」と促す
- 段階3が終わったら「工夫例を見てみましょう」
- 工夫例 1-3 のいずれかを実装
```

#### 工夫例まで完成した場合
```
対応方法：
- 「他のオプションも見てみたい？」と提案
- 別のオプション（例：A から H へ）へ移行
- または、より高度な工夫例へ
- 発表で複数のオプション組み合わせを紹介
```

### つまずきが多発している場合

#### 複数生徒が同じつまずきをしている場合
```
対応方法：
- 全体に向けて説明（個別ではなく）
- スクリーンを使ってコード例を投影
- つまずきポイント表から対応方法を引用
- 「これは多くの人がつまずくポイントです」と安心感を与える
```

#### 特定の生徒だけが大幅に遅れている場合
```
対応方法：
- 別のコーチに割当（複数コーチ運用の場合）
- 段階を簡略化（段階2はスキップして段階3へ）
- または、段階1で完成させる
- 発表では「工夫例」部分を紹介
```

## 📋 緊急時対応

### 急な環境トラブル

#### ブラウザがクラッシュした場合
```
対応：
- 再度 VS Code を起動
- ブラウザをリロード
- ローカルストレージをクリア
- 再度アクセス
```

#### インターネット接続が切れた場合
```
対応：
- p5.js がすでにロードされていれば動作継続可能
- オフラインモードで実装継続
- 音声機能（BGM）は使えない可能性
```

#### コーチが説明に詰まった場合
```
対応：
- 「いい質問ですね。一緒に確認しましょう」
- 虫食い問題の「解説」セクションを読む
- またはコーチガイドで対応方法を確認
- わからないなら「次で調べます」と正直に
```
