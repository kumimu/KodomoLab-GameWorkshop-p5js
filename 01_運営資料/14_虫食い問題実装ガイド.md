# 虫食い問題実装ガイド

虫食い問題を使った LESSON_6 オプション実装のコーチングマニュアル

---

## 🎯 ガイドの目的

生徒が LESSON_5 完了後、選んだ LESSON_6 オプション（A/B/G/H/M）を「虫食い問題」を通じて段階的に実装する際の、コーチ向けサポートガイド。

---

## 📋 虫食い問題の使い方

### コーチの役割

```
1. 生徒が LESSON_5 を完成させたことを確認
2. 5つのオプションの説明をする（5分程度）
3. 生徒が選んだオプションの虫食い問題を見せる
4. 「段階1から始めてみて」と指示
5. つまずいたら、ヒントを与える（答えは最後の手段）
6. 各段階が完成したら、テスト方法を一緒に実行
7. 次の段階に進むか、応用課題に進むか相談
```

## 🔍 各オプション別・実装検証

### OPTION A：敵の多様化（難易度★★★）

**実装検証チェック：**

| 項目 | 確認方法 | 成功基準 |
|------|--------|--------|
| **段階1完成** | type が設定されているか | コンソールで敵の type が表示される |
| **段階2完成** | 敵再生成時に type が更新されるか | 敵が画面下に消えて戻ってくるとき、type が変わる |
| **段階3完成** | 敵の見た目と速度が変わるか | 小さい敵が速く移動する |

**実装時間：30～45分**

**よくあるエラー：**

| エラー | 原因 | 解決方法 |
|--------|------|--------|
| 敵が全て同じサイズ | type 設定がされていない | startGame() の type 設定を見直す |
| 敵が小さく見えない | 描画サイズが変わっていない | drawEnemy() の条件分岐を確認 |
| エラーが出た | 変数名が違う | `enemy.type` の綴りを確認 |
| 速度が変わらない | moveEnemy() の条件が間違っている | if (enemy.type === 'fast') を確認 |

**コーチの対応：**

```
生徒がつまずいたら：

1. 「段階1で、type はどこに設定されましたか？」と質問
   → startGame() の敵生成部分を一緒に見る

2. 「type の値は何ですか？」と質問
   → 'fast' or 'normal' が正しいか確認

3. 「drawEnemy() で敵のサイズを確認してください」
   → if (enemy.type === 'fast') { circle(..., enemySize * 0.8) } を見直す

4. 「敵が小さいのに速く見えない」
   → moveEnemy() で speed * 1.5 が正しいか確認
```

### OPTION B：射撃機能（難易度★★★★）

**実装検証チェック：**

| 項目 | 確認方法 | 成功基準 |
|------|--------|--------|
| **段階1完成** | bullets 配列が作成されたか | コンソールで bullets が見える |
| **段階1.5** | スペースキーで弾が発射されるか | 敵に向かって黄色い弾が飛ぶ |
| **段階2完成** | updateBullets() で当たり判定が動くか | 弾が敵に当たると両方消える |
| **段階3完成** | playGame() に統合されているか | ゲーム中に弾が表示される |

**実装時間：45～60分**

**よくあるエラー：**

| エラー | 原因 | 解決方法 |
|--------|------|--------|
| 弾が発射されない | keyPressed() が正しくない | スペースキーの処理を確認 |
| 弾が見えない | drawBullets() が呼ばれていない | playGame() に drawBullets() が追加されているか確認 |
| 弾が敵をすり抜ける | 当たり判定の距離計算が間違っている | `hypot()` と距離の判定値を確認 |
| 敵が 1 つだけ消える | ループが途中で止まる | `break` または `continue` の使い方を確認 |
| スコアが加算されない | score += が正しくない | updateBullets() の score 加算処理を確認 |

**コーチの対応：**

```
生徒がつまずいたら：

1. 「スペースキーで弾が飛びますか？」
   → keyPressed() でスペースキー処理を見直す

2. 「弾は見えていますか？」
   → drawBullets() が playGame() に追加されているか確認

3. 「当たり判定の計算を見てください」
   → hypot() の使い方と距離の判定値（10 + enemySize / 2）を確認

4. 「敵が複数いるときはどうなりますか？」
   → for ループと splice() の使い方を見直す
   → break で途中で止まっていないか確認
```

**段階的な実装順序の推奨：**

```
段階1：bullets 配列を作成
  ↓
段階1.5：keyPressed() でスペースキー処理を追加（弾発射）
  ↓
段階2a：updateBullets() で弾を移動
  ↓
段階2b：updateBullets() で敵との当たり判定を実装
  ↓
段階3：playGame() に統合
```

### OPTION G：BGM のカスタマイズ（難易度★★☆）

**実装検証チェック：**

| 項目 | 確認方法 | 成功基準 |
|------|--------|--------|
| **段階1完成** | 変数が作成されたか | `bgmTimer`, `bgmIndex` が定義されている |
| **段階2完成** | BGM が再生されるか | ゲーム中にドレミファソラシド が聞こえる |
| **段階3完成** | ゲーム開始時に初期化されるか | ゲーム再開時に BGM も初期化される |

**実装時間：20～30分**

**よくあるエラー：**

| エラー | 原因 | 解決方法 |
|--------|------|--------|
| 音が出ない | ブラウザの音声設定 | ブラウザのスピーカー設定を確認 |
| sound() が見つからない | p5.js 関数でない | sound() は p5.sound ライブラリ（ブラウザ組み込み音声機能） |
| メロディが単調 | 周波数配列の値が同じ | BGM_MELODY の値を確認 |
| メロディが速すぎる / 遅い | % の値が不適切 | % 15 を調整（小さい→速い、大きい→遅い） |
| bgmIndex が無限に増える | % による限度設定がない | `bgmIndex % BGM_MELODY.length` を確認 |

**コーチの対応：**

```
生徒がつまずいたら：

1. 「音は聞こえていますか？」
   → ブラウザのスピーカー設定を確認
   → 別のゲーム（YouTube等）で音を確認

2. 「メロディが聞こえない」
   → playGame() に音声再生処理が追加されているか確認
   → startGame() で bgmTimer, bgmIndex が初期化されているか確認

3. 「メロディが速すぎる / 遅い」
   → % 15 の値を変更させてみる
   → 小さい値（% 10） = 速い
   → 大きい値（% 20） = 遅い
```

### OPTION H：ビジュアルカスタマイズ（難易度★★☆）

**実装検証チェック：**

| 項目 | 確認方法 | 成功基準 |
|------|--------|--------|
| **段階1完成** | 敵が回転するか | 敵が回転しながら落ちてくる |
| **段階2完成** | プレイヤーに光があるか | プレイヤーの周りに光の円が見える |

**実装時間：20～30分**

**よくあるエラー：**

| エラー | 原因 | 解決方法 |
|--------|------|--------|
| 敵が画面の左上で回転する | translate() がない | push/translate/rotate/pop の流れを確認 |
| 敵が回転しない | rotate() の値が 0 | frameCount * 0.05 を確認 |
| プレイヤーの光が見えない | 色が透明すぎる | fill(playerColor, 100) の 100 を大きくする（255 に近づける） |
| 敵が描画されない | circle() の座標が間違っている | translate 後は circle(0, 0, size) にする |

**コーチの対応：**

```
生徒がつまずいたら：

1. 「敵が左上で回転していますか？」
   → push/translate/pop の構造を一緒に見る

2. 「回転が遅い / 速い」
   → frameCount * の係数を変更（0.05 → 0.1 で 2 倍速）

3. 「プレイヤーの光が見えない」
   → fill(playerColor, 100) の 100 を大きくする
   → 255 に近づけると不透明になる
```

### OPTION M：スコアシステムの工夫（難易度★★★）

**実装検証チェック：**

| 項目 | 確認方法 | 成功基準 |
|------|--------|--------|
| **段階1完成** | 敵に value が設定されているか | コンソールで敵の value が見える |
| **段階2完成** | コンボ変数が作成されたか | `combo`, `comboTimer` が定義されている |
| **段階3完成** | スコアが異なるか | 通常敵 10 点、レア敵 50 点 |
| **段階4完成** | コンボが機能するか | スコアが倍になる（コンボ 5 以上） |
| **段階5完成** | コンボが表示されるか | 画面に "COMBO: Nx" が表示される |
| **段階6完成** | コンボがリセットされるか | 一定時間でコンボが 0 に戻る |

**実装時間：30～45分**

**よくあるエラー：**

| エラー | 原因 | 解決方法 |
|--------|------|--------|
| スコアが加算されない | moveEnemy() の処理が実行されていない | コンソール（F12）でエラー確認 |
| コンボが表示されない | drawGameInfo() に追加されていない | text("COMBO: " + combo + "x", ...) を確認 |
| コンボが永遠に続く | comboTimer の減少が正しくない | playGame() の timer 更新確認 |
| コンボ倍率が変わらない | floor() の計算が間違っている | console.log(combo, comboMultiplier) で確認 |
| レア敵が出現しない | isRare の確率が低すぎる | random() < 0.15 の値を大きくする |

**コーチの対応：**

```
生徒がつまずいたら：

1. 「スコアが加算されていますか？」
   → moveEnemy() の敵が画面下に消える処理を確認

2. 「コンボが表示されていますか？」
   → drawGameInfo() にコンボ表示が追加されているか確認

3. 「コンボが永遠に続きますか？」
   → playGame() で comboTimer-- が実行されているか確認

4. 「レア敵が見つかりません」
   → random() < 0.15 の値を 0.3 に変更して出現率を上げてみる

5. 「複数個の式をまとめるのが難しい」
   → const baseScore = enemy.value;
      const comboMultiplier = 1 + floor(combo / 5);
      score += baseScore * comboMultiplier;
      と分割して書かせる
```

## 💡 複数オプション実装時のコツ

### 順序推奨：A → G → H → M → B

**理由：**
1. A（敵拡張）は基本。ここから始める
2. G, H（装飾系）で楽しさを追加
3. M（スコア）で複雑な計算を学ぶ
4. B（射撃）は最も複雑。最後に

**時間目安：**
- A + G = 50～75分
- A + H = 50～75分
- A + G + H = 70～105分
- A + M = 60～90分
- すべて = 180分以上（1セッションには収まらない）
