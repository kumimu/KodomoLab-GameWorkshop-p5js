### タスク18：コーチ向けガイドの作成
**目的：** ワークショップコーチが、生徒の選択肢をサポートするための資料を作成

**作成ファイル：**
`01_運営資料/09_コーチ向けLESSON_6サポートガイド.md`

**含めるべき内容：**

#### セクション1：生徒がオプションを選んだときの対応フロー
```
生徒：「A. 敵の多様化を選びました」
コーチ：
1. LESSON_6A_敵の多様化.md を読むよう指示
2. 段階1（2種類の敵）から実装するよう勧める
3. 段階2（見た目の工夫）で色を変えることを確認
4. 段階3（動きの工夫）で sin() を使った揺らす動きを説明
5. 工夫例5種類から生徒の興味に合うものを一緒に検討
```

#### セクション2：各レッスン別の「つまずきやすいポイント」と対応方法

**LESSON_6A の場合：**
- つまずき1：`if (e.type === 'fast')` の if 文の書き方がわからない
  → LESSON_3（プレイヤーの移動）の「if 文」セクションへのリンク
- つまずき2：敵が画面に表示されない
  → `drawPolygon()` 関数が正しく実装されているか確認
- つまずき3：敵の種類が均等に出現しない
  → `random()` の確率計算を確認

同様に B, G, H, M ごとに記載

#### セクション3：工夫例への段階的な指導
```
段階1（最小限実装）：生徒が自分で実装可能なレベル
  → コーチは見守る

段階2〜3（工夫段階）：提供されている工夫例から選ばせる
  → コーチが「どの工夫例にしようか」と相談する形で対応

段階4以上（完全オリジナル）：工夫例を参考に独自の実装
  → コーチがコードレビューして、ロジックが正しいか確認
```

#### セクション4：複数のオプションを組み合わせた場合の対応
```
例：「敵の多様化（A）と射撃機能（B）の両方やりたい」
→ 見積もり時間：60分×2 = 120分
→ 実装順序：まず A を完成させ、次に B を追加
→ コンビネーション例：敵の種類によって射撃の効果が異なる

#### セクション5：時間が余った場合の発展課題

```
「敵の多様化（A）を完成させたが、まだ時間がある」
→ 提案1：参考資料「難易度調整（L）」で敵の出現頻度を変える

→ 提案3：「ビジュアルカスタマイズ（H）」で敵の形をもっと工夫

#### ゲーム側の質問
- Q：「敵の多様化と射撃機能の両方やりたいことはできる？」
  A：「はい、できます。LESSON_6_オプション一覧.md で、同じセッション内に複数やることについて説明しています」

- Q：「射撃機能を実装しているのに、敵に当たらない」
  A：「当たり判定の計算に誤りがないか確認してください。LESSON_4 の dist() 関数を見直してください」

- Q：「BGM が重なって聞こえる」
  A：「複数の playSound() が同時に呼ばれていないか確認。bgmTimer をリセットしているか確認」

#### 実装側の質問
- Q：「敵のタイプをもっと増やしたいけど、どうする？」
  A：「type のチェック部分を if-else if でどんどん増やしていけます。工夫例1を参照」

- Q：「コンボを表示しているのに画面に出ない」
  A：「text() 関数で combo の値が 1 より大きいか確認。fill() で色を設定していますか？」

- Q：「スコアの倍率が複雑になった」
  A：「console.log() でスコア計算の各段階を出力して、どこが間違っているか探ってください」

#### 概念的な質問
- Q：「type とは何ですか？」
  A：「敵オブジェクトが持つ『種類』を示す情報です。敵1は 'fast'、敵2は 'slow' といった感じで分類します」

- Q：「周波数シーケンス配列とは何ですか？」
  A：「複数の周波数（音の高さ）を配列で並べたもの。この配列を順番に再生すると、メロディになります」

- Q：「コンボが途中で途切れる」
  A：「comboTimer の設定時間内に敵を倒さないと途切れます。LESSON_6M の段階3を見てください」

#### 技術的な質問
- Q：「push() と pop() が何をしているかわからない」
  A：「push() は『ここからの変更を保存』、pop() は『変更を取り消す』という意味です。LESSON_6H を見直してください」

- Q：「rotate() で回転がおかしい」
  A：「rotate() の前に translate() で中心を移動する必要があります。工夫例5を参照」

## 📌 重要なポイント

### 資料作成時の注意

1. **コード例の正確性が最優先**
   - 実際に NEON DODGE で動作するか確認してから掲載
   - 不正確なコード例は生徒を混乱させる

2. **コーチと生徒の役割を明確に**
   - コーチ向け資料には「何を説明するか」を明記
   - 生徒向け資料には「難しい概念は避ける」

3. **段階的実装のレベル設定**
   - 段階1：最小限（30分以内に実装可能）
   - 段階2：基本的な工夫（30〜60分）
   - 段階3：複雑な工夫（60分以上）
   - 段階4：完全オリジナル（オープンエンド）

4. **複数オプション同時実装への対応**
   - 時間見積もりを明確に
   - 実装順序を提案
   - 組み合わせの効果を説明
