# 講師用進行台本（90分）

対象：中学生、事前学習不要。参加者数・コーチ数は開催前に確定。全員の1つ以上の改造・試遊・保存がゴール。応用課題はA/B/G/H/Mから本人が1つ選び、コピーと空欄補充でシンプル版へ実装する。NEON DODGEは完成見本として扱う。

準備は[開催準備チェックリスト](../04_事前準備/07_開催準備チェックリスト.html)を確認します。授業中は最新版の[生徒用テキスト](../01_生徒/02_ワークショップテキスト.html)を画面共有し、この台本で時間・声掛け・支援の判断を確認します。

## 基礎練習の実演（10～25分）

- 10～15分：練習画面を示し、40を80、次に20へ。「何が変わる？」と予想を聞いてから保存・Chrome更新。
- 15～20分：cyanをyellowへ。タイトルの引用符の内側も変更。日本語と半角記号の切替を補助。
- 20～25分：playerSizeという名前と値、circleの中心座標・直径を示す。100とblueの確認クイズを実施。
- 全文入力やアカウント登録はこの15分に含めない。開始コードは事前配布。開始前にローカル練習ファイルを開き、保存・Chrome更新を確認する。
- 25分でゲーム本体を開き、生徒テキストの「ゲーム全体の地図」で全体を7分説明する。基礎練習も本体も、VS Code保存→Chrome更新に揃える。Web Editorを使う場合のみ▶との違いを補足する。

## 改造の選び方（35～55分）

全員、現在のシンプル版を使う。A敵・B射撃・G BGM・H見た目・Mスコアから、作りたいものを本人が1つ選ぶ。生徒用の[課題の選び方](../01_生徒/応用課題/00_課題の選び方.html)を開き、選んだ機能のコードだけを、末尾の応用コード貼り付け欄へ1回貼って虫食いを埋める。完成見本のNEON DODGEは編集しない。35～38分に選択とワーク用の保存、38～48分にコピー・空欄、48～55分に確認と自分の工夫を目安にする。

この20分は実測した所要時間ではない。詳細資料の全段階を口頭で教えるのではなく、当日用の短い課題とヒントを使う。コピー位置で止まった生徒へ早めにコーチを回し、解答例も支援に使う。

50分に「新しい改造はあと5分」と予告。55分に必ず仕上げへ。55分以降は新しい課題へ切り替えず、現在のワーク用を保存して確認へ進む。

## 遅れ・故障時の判断

- 35分で色・速さの変更と操作確認ができていない人を優先。次の課題を増やさない。
- 55分からの5分で仕上げ。直前の変更を確認し、必要ならオリジナルと比較して修正する。
- 60分でまだ動かない場合は、保存した動く版で確認・試遊へ。本人ができた変更や気づきも紹介できるよう支援。
- 同じエラーが複数人に出たら全体説明は2分を目安にし、個別支援へ戻る。
- PC故障は予備機・ペア作業へ。通信断は用意したローカル練習版へ。
- 70分で入れ替えプレイ、85分で保存へ。後半を追加実装に振り替えない。

## 試遊と共有

70〜80分は席を入れ替えてプレイする。2人組は互いに交換し、3人組は1席ずつずらす。感想交換・ノート記入・発表準備は行わない。80〜85分の全体共有は希望者2〜3名とする。

## FAQ（講師・コーチ共通）

| 質問・症状 | 確認と説明 |
|---|---|
| Web Editorで変化しない | ▶で再実行。ローカル版なら保存とブラウザ更新。2つの操作を混同しない |
| ゲームが変化しない | ファイルの場所、表示中HTML、保存・更新の順に確認 |
| 円の200と150は？ | 左上から測った中心座標。playerSizeは直径。ゲームの自機は三角形 |
| タイトルを改行したい | 文字列内に半角の\n。Enterによる直接改行はしない。任意課題として見本からコピー可 |
| 数値に引用符は必要？ | 今日の数値設定は付けず、色名やタイトルは半角の引用符で囲む |
| キーが反応しない | 画面をクリック。日本語入力をオフにし、ゲームの状態ごとの操作を確認 |
| 赤いエラーが出る | 直前の1か所と、引用符・カンマ・括弧を確認。まず本文のエラーを一緒に読む |
| 虫食いはどこへ貼る？ | シンプル版sketch.js末尾の応用コード貼り付け欄。選んだ機能だけを1回貼る。ゲーム全体は置き換えない |

| 完成見本のモードは？ | スターは7秒無敵と全得点2倍。12体撃破でも最低4秒の無敵。連射強化は12秒の3方向射撃。シールドは次の被弾まで1回分 |
| 元に戻したい | 直前の変更を元に戻して確認する。直らなければオリジナルと必要箇所を比較して修正し、本人の改造を無断で一括破棄しない |
| ライセンスは？ | 実行用ライブラリとlicensesを含むフォルダ全体を配布する。THIRD_PARTY_NOTICES.mdを参照 |

## 実施記録（終了後）

計画は所要時間を実測した記録ではない。35・55・60・70・85・90分の実際の進行、改造・試遊・保存の達成人数、つまずきと対応を記録し、次回へ反映する。

## 25～32分のコード読み合わせ

- 25～26分：3ファイルの役割と読み込み順。index.htmlからp5、ゲームの順で読む。
- 26～27分：setupは準備、drawは繰り返し。gameStateのstart→play→endをゲーム画面で示す。
- 27～28分30秒：変数は記録、enemiesは一覧、enemyは1体。x・y・speedを指す。forは各敵に同じことをする繰り返し。
- 28分30秒～30分：左右のx、落下のy、端のconstrain、距離のisHitを指す。三平方の証明はこの場で扱わない。
- 30～32分：本体が登録機能のstart/key/update/drawを呼ぶ。Bを例に弾の一覧this.bullets、pushで追加、spliceで削除を説明する。
- 32分から「ゲーム本体の色とスピードを変える」へ。35分に「課題の選び方」でA〜Nを紹介し、本日の5テーマを選ぶ。各テーマの詳しい仕組みは選択後のコーチ説明で補う。

この配分はリハーサルで確認する。全体像7分＋色・速さの変更3分に組み替え、応用課題の35～55分は確保する。

## 32～35分の最初の改造

「先ほどの練習と同じように、変数の値を変えて、実際のゲームもカスタムしてみましょう。まずは自機を好きな色に。さらに今回は、自機のスピードも変えて、操作した感じがどう変わるか試してみましょう。」と案内する。CUSTOM AREAのplayerColorを好きな色にし、playerSpeedを7から12へ。保存・本体の更新・1で開始し、数秒左右へ動かして違いを確認する。クリアは待たず、35分に応用課題へ進む。

### 追加機能の説明：複数の課題の登録

registerWorkshopOptionは本体にある共通関数。課題コードはA・B・G・H・Mの異なるIDで呼び出す。ID別にデータを持つため複数の機能を追加できる。this.bulletsはBのデータ。同じIDをもう一度登録すると最後の内容へ置き換わる。生徒に登録関数の名前を変更させない。


## フォルダ運用

開始前に同じ初期内容の「オリジナル」「ワーク用」を各PCへ配置する。オリジナルは参照・復旧用で編集しない。全ての練習・改造・ブラウザ実行はワーク用で行い、途中で保存用コピーを作る作業は挟まない。原本は最後に動いた版ではなく最初の状態なので、復旧では改造を失わないよう必要な箇所を比較して直す。最後の5分はワーク用全体をUSBへコピーし、コピー先で起動確認する。
