# 講師用進行台本（90分）

対象：中学生、事前学習不要。参加者数・コーチ数は開催前に確定。全員の1つ以上の改造・試遊・保存がゴール。応用課題はA/B/G/H/Mから本人が1つ選び、機能コードのコピーと空欄補充でシンプル版へ実装する。NEON DODGEは持ち帰り用の完成見本で、当日の改造には使わない。

## 手元に開いておく資料

- **投影用**：[投影用まとめ](05_投影用まとめ.html)。基礎練習と最初の改造で使う。②の見出しから[コードと解説（5画面）](06_コードと解説.html)へ進み、解説後は「投影用まとめ」リンクで戻る。
- **生徒の手順・詳細確認**：[生徒用テキスト](../01_生徒/02_ワークショップテキスト.html)。全編を読み上げず、実習で必要な手順を確認する。LESSON_1～5は詳しい参考資料として残す。
- **35分以降**：[課題の選び方](../01_生徒/応用課題/00_課題の選び方.html)。選んだ課題のページで、予想・コード・空欄のヒント・動作確認を進める。
- **開始前**：[開催準備チェックリスト](../04_事前準備/07_開催準備チェックリスト.html)。オリジナルとワーク用を各PCへ準備し、ファイルを開く作業は開始前に済ませる。

講師はこの台本を手元で使い、説明時は投影資料、実演時はVS CodeとChromeの実行画面を示す。生徒が今編集するファイル名と、更新する画面を毎回伝える。

## 基礎練習の実演（10～25分）

編集は「ワーク用／JS_15分入門／practice.js」、実行は同じ練習フォルダのindex.html。まとめ①で内容を示し、VS Codeで既存の値を変更して、保存→Chrome更新を実演する。

- 10～15分：playerSizeを80、次に20へ。「何が変わる？」と予想を聞いてから保存・更新する。
- 15～20分：playerColorをyellowへ。gameTitleの引用符の内側も変更。日本語入力後は英数へ戻す。
- 20～25分：playerSizeという名前と値、circleの中心座標・直径を示す。最後に100とblueへ変え、青い円になるか確認し、ノートへ短く記録する。

全文入力やアカウント登録は含めない。開始コードは事前配布し、練習ファイルを開いて保存・更新できることを開始前に確認する。25分には練習を止め、まとめ②へ進む。

## 最初の改造（32～35分）

> 先ほどの練習と同じように、変数の値を変えて、実際のゲームもカスタムしてみましょう。まずは自機を好きな色に。さらに今回は、自機のスピードも変えて、操作した感じがどう変わるか試してみましょう。

- 32:00～32:45：ワーク用のsketch.jsを開き、CUSTOM AREAのplayerColorを好きな色にする。色名の引用符は残す。
- 32:45～33:15：playerSpeedを7から12へ変える。数値には引用符を付けない。
- 33:15～34:30：保存→Chromeのゲーム本体を更新→画面をクリック→英数入力で1→左右キーで操作。「速いと避けやすい？ 動きすぎて難しい？」と問いかける。
- 34:30～35:00：確認できたことを確かめ、[課題の選び方](../01_生徒/応用課題/00_課題の選び方.html)へ切り替える。クリアまで待たない。

練習のpractice.jsで変えた値はゲーム本体に自動では移らない。画面やファイルを間違えた人にはコーチが個別に対応し、全体は35分に応用へ進む。

## 応用課題の選択と実装（35～55分）

A〜Nは14テーマの一覧として短く紹介し、本日の改造対象は○の付いたA・B・G・H・Mの5つと伝える。本日対象外のテーマも、持ち帰る完成版を参考に家で改造できる。全14テーマの個別説明は行わない。

| 時刻 | 生徒の作業 | 講師・コーチの支援 |
|---|---|---|
| 35～38分 | 作りたい機能を1つ選び、ノートへ記録。ワーク用のsketch.jsを保存 | A：敵の多様化／B：射撃／G：BGM／H：見た目／M：スコアを短く紹介し、選んだ課題ページを開く |
| 38～48分 | 課題ページの予想問題を選び、機能コードをコピー。末尾の貼り付け欄へ貼り、虫食いを埋める | 貼る場所・残った空欄・半角の記号を確認。let bulletsなどを別の場所へ追記させない |
| 48～55分 | 保存・更新・動作確認。値を変えて比べ、自分の意図をコメントに書き、ノートに記録 | 課題ページの動作確認を使う。1つ目を確認できた人は、希望すれば別の機能を同じ欄へ追加できる |

各課題ページの手順とヒントを使い、詳細資料を全員に読み上げない。詰まった人には[コーチ用の解答と確認](../03_コーチ/07_虫食い課題の解答と確認.html)も使う。選んだ機能のコードだけを1回貼り、ゲーム全体は置き換えない。CUSTOM AREAの色・速さは残す。

50分に「新しい改造はあと5分」と予告し、55分に追加を止める。55分以降は新しい課題へ切り替えず、現在のワーク用を保存して確認へ進む。この20分の配分も、リハーサルで実測する。

### コーチが質問されたときの補足：追加機能の登録

この節は全体説明では読み上げない。registerWorkshopOptionは本体にある共通関数。A・B・G・H・Mの異なるIDごとにデータを持つので複数機能を追加できる。同じIDを再登録すると最後の内容へ置き換わる。登録関数の名前は変更しない。this.bulletsやpush・splice等は、該当の課題を選んだ生徒への補足に留める。

## 遅れ・故障時の判断

- 25分：基礎練習を終え、解説へ。未完了の人はコーチが個別支援する。
- 32分：解説を終え、最初の改造へ。オプションの内部や数式の詳しい質問は後で個別に扱う。
- 35分：全体は応用課題へ。色・速さの変更や操作確認で止まっている人をコーチが優先支援する。
- 55分：新しい改造を止め、まず保存。直前の変更を確認し、必要ならオリジナルの該当箇所と比較する。
- 60分でも動かない場合：コーチと直前の変更を戻す。追加した課題が原因なら、その課題のコードを外して動作を確かめ、色や速さなど動く変更は残す。戻す範囲を本人と確認し、ワーク用を原本で丸ごと上書きしない。
- 同じエラーが複数人に出たら、共通の確認事項を2分以内で示して個別支援へ戻る。
- PC故障は予備機・ペア作業へ。教材はローカルで実行するため、通信断でも同じファイルで続ける。
- 70分に入れ替えプレイ、85分にUSB保存へ。後半を追加実装に振り替えない。

## 試遊と共有

70～80分は席を入れ替えてプレイする。2人組は互いに交換し、3人組は1席ずつずらす。感想交換・ノート記入・発表準備は行わない。80～85分の全体共有は希望者2～3名とする。

## FAQ（講師・コーチ共通）

| 質問・症状 | 確認と説明 |
|---|---|
| ゲームが変化しない | ファイルの場所、表示中HTML、保存・更新の順に確認 |
| 円の200と150は？ | 左上から測った中心座標。playerSizeは直径。ゲームの自機は三角形 |
| タイトルを改行したい | 文字列内に半角の\n。Enterによる直接改行はしない。任意課題として見本からコピー可 |
| 数値に引用符は必要？ | 今日の数値設定は付けず、色名やタイトルは半角の引用符で囲む |
| キーが反応しない | 画面をクリック。日本語入力をオフにし、ゲームの状態ごとの操作を確認 |
| 赤いエラーが出る | 直前の1か所と、引用符・カンマ・括弧を確認。まず本文のエラーを一緒に読む |
| 虫食いはどこへ貼る？ | シンプル版sketch.js末尾の応用コード貼り付け欄。選んだ機能だけを1回貼る。ゲーム全体は置き換えない |
| 空欄を埋めても変化しない | 保存と更新を確認し、機能ごとのIDと空欄、追加前の機能も動くかを調べる。__A1__等の印が残っていないか確認 |
| 完成見本のモードは？ | スターは7秒無敵と全得点2倍。12体撃破でも最低4秒の無敵。連射強化は12秒の3方向射撃。シールドは次の被弾まで1回分 |
| 元に戻したい | 直前の変更を元に戻して確認する。直らなければオリジナルと必要箇所を比較して修正し、本人の改造を無断で一括破棄しない |
| ライセンスは？ | 実行用ライブラリとlicensesを含むフォルダ全体を配布する。THIRD_PARTY_NOTICES.mdを参照 |


## フォルダ運用と持ち帰り

開始前に同じ初期内容の「オリジナル」「ワーク用」を各PCへ配置する。オリジナルは参照・復旧用で編集しない。練習・改造・実行はワーク用で行い、途中で保存用コピーを作らせない。

85分になったらVS Codeですべて保存し、ワーク用フォルダ全体をUSBへコピーする。index.html、sketch.js、p5.min.js、licenses、JS_15分入門をまとめて持ち帰る。USB内のindex.htmlから開き、コピーしたゲームが動くことを確認する。完成見本は編集したワーク用と区別して渡す。

## リハーサルと実施記録

この台本の時間は計画であり、時間内に収まることを実測で確認した記録ではない。次のリハーサルでは、講師の説明だけでなく、生徒役の保存・画面更新・ファイル切り替えも含めて測る。

- 25～32分：まとめから5画面へ進み、まとめ③に戻るまでを測る。オプションの説明を加えず7分に収められるか。
- 32～35分：好きな色・速さの変更から実行確認までを測る。
- 35～55分：課題選択から1つ目の動作確認までを測る。止まった場所と必要な支援を記録する。
- USBへのコピーと起動確認が最後の5分でできるか、実際のPC・USBで確認する。

終了後は35・55・60・70・85・90分の実際の進行、改造・試遊・保存の達成人数、つまずきと対応を記録し、次回へ反映する。
