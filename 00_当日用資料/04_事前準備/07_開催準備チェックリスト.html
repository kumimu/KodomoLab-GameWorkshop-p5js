開催準備チェックリスト（90分）

講師・コーチ・準備担当が、開催前に確認する資料です。資料やファイルで確認済みの項目には、あらかじめチェックを付けています。当日の項目は、会場のPCやUSBで確かめてからチェックします。インストール・教材配布・ファイルを開く準備・印刷は、開始前に済ませます。

当日はシンプル版を使い、ゲームで遊ぶ→15分の基礎練習→ゲームの仕組み→色・速さの変更→応用課題の順で進めます。

1　開催条件と担当

  • 日時、参加人数、講師・コーチの人数と担当範囲を確定した。
  • 個別支援を担当するコーチを決めた。
  • 全員がシンプル版を使い、応用はA・B・G・H・Mから本人が1つ選ぶ方針を共有した。
  • 予備PCと、故障時に使う席・ペア作業の方法を決めた。
  • 入れ替えプレイの組み方を決めた。(隣同士で実施。参加者が奇数の場合は調整)
  • 隣り合う2人席3組で、70～80分に改造の紹介・入れ替えプレイ・口頭での感想交換を行う。コーチの担当を確認し、入れ替えプレイのタイミングは講師がアナウンスすると共有した。

2　当日資料と投影の準備

当日資料一覧から、使う資料を開きます。

  • 生徒用のアジェンダ・テキスト・ノートを用意した。
  • ノートの印刷2ページを印刷した。
  • ワークショップテキスト（投影用）、投影用まとめとコードと解説（5画面）を開き、投影時の文字サイズと表示を確認した。
  • 投影用テキストのT04前半から「ゲームの仕組みを見る」で投影用まとめへ進み、コード解説の「ワークショップテキストに戻る」でT04後半へ戻れた。
  • 全体へのコード解説では基本の動作を扱い、灰色のオプション用コードの内部は説明しない。
  • 投影用テキストのT02から避けゲームと発展版ゲームを別タブで開き、デモプレイ後に投影用テキストのタブへ戻る操作を試した。
  • コーチはフォローガイド・解答と確認・命中音のTIPS(任意)を参照できる。

3　各PCのフォルダとソフト

配布元は02_教材／01_配布テンプレートです。開始前に同じ初期内容の「オリジナル」「ワーク用」を用意します。どちらもindex.html、sketch.js、p5.min.js、licenses、JS_15分入門を含むフォルダ全体を揃えます。

フォルダ 使い方
オリジナル 初期状態の参照・復旧用。編集しない
ワーク用 生徒が練習・改造・実行する。最後にUSBへコピーする
完成見本 発展版ゲーム。シンプル版で遊んだ直後（9〜10分）に講師が実演。ワーク用と区別して持ち帰る

当日の確認（開始前）

  • 開始前に、持ち帰り用USBへ「オリジナル」と「発展版ゲーム（完成版）」をフォルダごとコピーした。
  • オリジナルとワーク用は開始時に同じ内容で、練習・改造の試行が残っていない。
  • 準備担当が各PCの「ワーク用」をGitで初期化し、練習・改造前の状態を初期コミットした。

    教材の動作確認を始める前に、準備担当が「ワーク用」フォルダ内で次のコマンドを実行し、配布時の状態を初期コミットします。

    git init
git add .
git commit -m "ワークショップ開始時の教材"
  • 各PCでVS Codeを起動し、配布フォルダを開けた。
  • 各PCのChromeで配布フォルダのindex.htmlを開けた。
  • VS Codeで練習用のpractice.jsを開けた。
  • VS Codeでゲーム用のsketch.jsを開けた。
  • Chromeでワーク用の避けゲームと基礎練習を開き、どちらの画面か見分けられる。
  • キーボード上段の1・2・3、左右キー、Spaceが使える。画面へのフォーカスと日本語入力オフも確認した。

4　ライブラリと最初の実習

同梱ファイルで版を固定し、当日に更新しません。基礎練習もローカルで実行します。

  • シンプル版のp5.min.js先頭で、p5.js 1.11.13を確認した。
  • 発展版ゲームのp5.min.js先頭で、p5.js 1.11.13を確認した。
  • ゲームのindex.htmlが同じフォルダのp5.min.jsを、基礎練習が親フォルダのp5.min.jsを読み込む構成を確認した。
  • 各教材のlicensesと、ライセンス・配布案内に記載された同梱物が揃っている。
  • JS_15分入門／index.htmlに円とタイトルが出て、practice.jsの大きさ・色・タイトルを変更できた。
  • 基礎練習の最後に、playerSizeを100、playerColorをcyanからyellowへ変え、直径100の黄色い円になることを確認した。
  • 避けゲームでplayerColorを好きな色、playerSpeedを7から12へ変え、保存・更新・1で開始・左右移動を確認した。
  • 自機の初期速度7と変更後12の違いを、数秒の操作で確かめる実演を準備した。
  • 動作確認で変更した「ワーク用」のファイルを初期コミットの状態に戻した。

5　5つの応用課題とコーチの支援

  • 課題の選び方のA〜N一覧を使い、本日は○のA・B・G・H・Mから選ぶと案内できる。
  • 5課題をそれぞれ初期状態のシンプル版へ貼り、空欄を埋めて単独動作を確認した。
  • 機能コードだけをsketch.js末尾の共通欄へ貼り、自機の色・速さの変更が残ることを確認した。
  • 早く進む人向けに、複数機能の併用・表示・終了・再開を確認した。同じ課題を再度貼る場合は、その課題だけを置き換えると案内できる。
  • 課題ページの予想問題、比較実験、意図をコメントに書く手順、動作確認をコーチが試した。
  • ゲームがうまく動かないときは、コーチが生徒と一緒に変更した箇所を確認する。必要に応じてオリジナルと見比べ、どこを直すか、どこを元に戻すかを相談すると案内できる。

6　配布・リハーサル・USB保存

  • 事前確認で、前半の流れ（オープニングから共通ハンズオンまで）を確認した。
  • 事前確認で、後半の流れ（オプション実装から作品レビュー、持ち帰りまで）を確認した。
  • USBを必要人数分用意し、実際のPCで認識・書き込み・空き容量を確認した。 (先方にてご対応いただく)
