# コーチ用フォローガイド

目的は、生徒が自分で1つ変えて確かめられるよう支援すること。答えを先に入力せず、まず「どこを変えた？」「どうなると思った？」を聞く。

## 開始前の担当確認

担当する参加者・予備PC・持ち帰り先を講師と確認。シンプル版、練習、発展版ゲーム（完成見本）を区別する。A/B/G/H/Mの当日用課題と[解答と確認](07_虫食い課題の解答と確認.html)を手元で開けるようにする。準備は[開催準備チェックリスト](../04_事前準備/07_開催準備チェックリスト.html)を参照する。

## 時間ごとの確認

| 時刻 | 成功の目印 | つまずいた人への支援 |
|---|---|---|
| 5～10分 | 開始・移動・終了後の戻り方を確かめ、ゲームの動きを観察できる | 画面をクリック。難易度を1にする |
| 10～25分 | 数値や文字を変え、円・タイトルに反映できる | ワーク用のpractice.jsを保存し、Chromeの練習画面を更新。引用符を残し値だけ変更 |
| 25～32分 | 準備→繰り返し描画→移動→当たり判定の流れを追える | まとめとコード解説5画面を参照。灰色のオプション用コードの内部は全体説明から外す |
| 32～35分 | 自機が好きな色になり、playerSpeedを7→12に変えて操作の違いを確かめられる | ワーク用のsketch.jsを保存→Chromeの避けゲームの画面を更新→画面をクリック→英数入力で1→左右キー。クリアは待たない |
| 35～55分 | 本人がA/B/G/H/Mから1つ選び、共通欄へ機能コードを1回貼り、空欄を埋める | 共通欄への貼り付けと、空欄の意味を説明。選択を勝手に変更せず、コピー・ヒント・解答例で支援 |
| 55～60分 | 動く版がある | 直前の変更を確認し、必要な箇所を講師とオリジナルで比較して直す |
| 60～70分 | 開始・移動・改造箇所・終了と再開を確認 | 未確認の項目は記録。全部終わったことにしない |
| 70～80分 | 隣同士で改造を紹介し、相手の作品を遊んで感想を伝え合う | 70～72分は紹介、72～78分は席を交換して試遊、78～80分は口頭で感想交換。講師が切り替えを合図し、コーチは発言が偏らないよう声をかける |
| 80～90分 | 本人がUSB内のゲームを起動できる | すべて保存し、ワーク用をlicensesごとUSBへコピー。USB内のindex.htmlから起動も確認 |

## 調べる順序

1. 生徒の説明と、直前に変えた場所を確認。
2. 編集・実行が同じワーク用か確認。円の練習はpractice.jsと練習のindex.html、ゲームはsketch.jsと「ワーク用」のindex.htmlを対応させ、VS Codeで保存→Chromeで対応する画面を更新する。
3. 最初のエラーを読み、引用符・カンマ・括弧・全角記号を確認。
4. 直前の変更だけを修正して保存・更新する。ゲームの操作確認では画面をクリックし、日本語入力をオフにして1で開始する。
5. 難しい場合は本人と変更内容を確認し、オリジナルと必要箇所を見比べて直す。原本でワーク用を丸ごと上書きしない。

`git restore sketch.js`を無断で実行しない。作品の保全と本人への説明を優先する。認証やpushの問題は授業内で解決を試みず、講師へ引き継ぐ。

## 応用課題の案内

A敵・B射撃・G BGM・H見た目・Mスコアの5つから、本人が好きな1つを選ぶ。貼り付け先はここまで編集したシンプル版のsketch.js。当日用課題はそれぞれ単独で動く構成で、他の課題の実装を前提にしない。発展版ゲームは完成見本として短く紹介し、持ち帰り後の改造に使う。

必要な準備はゲームのコードの共通処理に含めてある。選んだ機能だけのコードを末尾の共通欄へ1回貼る。コーチは機能の仕組み・空欄の意味を説明し、予想と結果を確認する。空欄の印を全て値へ置き換えてから、保存・更新して実行する。詳しい解答と課題別の確認は[解答と確認](07_虫食い課題の解答と確認.html)を使う。

生徒が工夫する値の意味を聞く。まずヒント例で動作させ、その後で自分の値に変えて確認する。

## FAQ（講師・コーチ共通）

| 質問・症状 | 確認と説明 |
|---|---|
| ゲームが変化しない | ワーク用のsketch.jsを編集しているか、「ワーク用」のindex.htmlを開いているか確認。保存→Chrome更新→1で開始 |
| 円の練習が変化しない | ワーク用のJS_15分入門／practice.jsを保存し、同じ練習フォルダのindex.htmlをChromeで更新 |
| 円の200と150は？ | 左上から測った中心座標。playerSizeは直径。ゲームの自機は三角形 |
| タイトルを改行したい | 文字列内に半角の\n。Enterによる直接改行はしない。任意課題として見本からコピー可 |
| 数値に引用符は必要？ | 今日の数値設定は付けず、色名やタイトルは半角の引用符で囲む |
| キーが反応しない | 画面をクリック。日本語入力をオフにし、ゲームの状態ごとの操作を確認 |
| 赤いエラーが出る | 直前の1か所と、引用符・カンマ・括弧を確認。まず本文のエラーを一緒に読む |
| 虫食いはどこへ貼る？ | シンプル版sketch.js末尾の応用コード貼り付け欄。選んだ機能だけを1回貼る。ゲーム全体は置き換えない |
| 空欄を埋めても変化しない | 保存と更新を確認し、機能ごとのIDと空欄、追加前の機能も動くかを調べる。__A1__等の印が残っていないか確認 |
| 発展版ゲームのモードは？ | スターは7秒無敵と全得点2倍。12体撃破でも最低4秒の無敵。連射強化は12秒の3方向射撃。シールドは次の被弾まで1回分 |
| 元に戻したい | 直前の変更を元に戻して確認する。直らなければオリジナルと必要箇所を比較して修正し、本人の改造を無断で一括破棄しない |
| ライセンスは？ | 実行用ライブラリとlicensesを含むフォルダ全体を配布する。THIRD_PARTY_NOTICES.mdを参照 |

## 講師への引継ぎ

「対象のPC／教材」「直前の変更」「エラーや症状」「試したこと」「現在のワーク用の場所と動作確認できた範囲」を短く伝える。全体が止まる問題や機器故障は早めに共有する。

## 説明から改造へつなぐ

講師は[投影用まとめ](../02_進行/05_投影用まとめ.html)と[コードと解説（5画面）](../02_進行/05_投影用まとめ.html#s1)で基本の流れを説明し、色と速さを変える実習へ進む。この全体説明では、登録関数・倍率の三項演算子・配列操作などの内部説明は加えない。選択後は、今日の機能がその地図のどこへ働きかけるかを示す。Bならキー入力→弾を追加→移動・命中→描画。用語を一度に全て教えず、生徒の選んだ課題のコードを指して説明する。A〜Nはテーマの記号で、本日はA/B/G/H/Mから改造する。


## 2つのフォルダの使い分け

オリジナルは初期状態の参照・復旧用、ワーク用は編集・実行用。途中で保存用フォルダを増やす指示はしない。動かなくなったら直前の変更を確認し、必要な箇所を原本と見比べて修正する。ワーク用を原本で丸ごと上書きすると、それまでの改造を失うため、本人と変更内容を確認してから対応する。持ち帰るのはUSBへコピーしたワーク用。
