# レッスン5：改造ミッションの指導

## 🎯 学習目標

ワークショップで参加者が行う改造ミッションを、難易度ごとに分析する。

- 各ミッションの内容と実装方法
- 難易度別のサポート方法
- よくあるエラーと対応
- コーチが生徒を導くためのヒント
- 時間内に完成させるための工夫

---

## 📋 改造ミッション一覧（参照）

**ファイル：** `missions.md`

```
★ レベル1（★1つ：基本中の基本）
- プレイヤーの色を変える
- 敵の色を変える
- 背景色を変える
- ゲームタイトルを変える

★★ レベル2（★2つ：数値調整）
- プレイヤーの速さを変える
- プレイヤーの大きさを変える
- 敵の大きさを変える
- 遊びやすい難易度に調整する

★★★ レベル3（★3つ：難易度ロジック）
- 難易度ごとの敵の速さを変える
- 難易度ごとの敵の数を変える
- 制限時間を変える
- 自分だけのテーマを考える

★★★★ 自由改造（★4つ：応用）
- 画像を使う
- 効果音を入れる
- BGMを入れる
- 新しいルールを追加する
```

ワークショップでは、松竹梅の3つを事前に選んでもらい、時間内に実装します。

## 🎨 レベル1：基本の色・テーマ変更

### ミッション1-1：プレイヤーの色を変える

**難易度：** ⭐ 最も簡単

**変更ファイル：** `sketch.js` の7行目

```javascript
// 元
let playerColor = "cyan";

// 変更例
let playerColor = "lime";
let playerColor = "#FF6B9D";
```

**実装時間：** 1分

**生徒がつまずく可能性：**
- 色名のスペルが違う（`"Green"` ではなく `"green"`など）
- セミコロン `;` を忘れる
- 保存忘れ、またはブラウザの更新忘れ

**コーチが出すヒント：**
1. 「p5.jsの色名で、好きな色を探してみて」
2. 「'lime', 'yellow', 'pink' などの色名が使えます」
3. 「セミコロンをつけて、保存してから F5 で更新してね」
4. 「カラーピッカーを使えば、好きな色の16進数が分かりますよ」

**コーチが教える前に確認すること：**
- 生徒が、CUSTOM AREA のどこを変更するのか理解しているか
- 正しい色名を入力しているか
- 保存と更新のステップを忘れていないか

**代替案（完成できなかった場合）：**
色名リストを提示して、その中から選ばせる：

```javascript
// 用意した色名
"cyan"     // シアン（水色）
"lime"     // ライム（黄緑）
"yellow"   // 黄
"orange"   // オレンジ
"pink"     // ピンク
"purple"   // 紫
```

## ⚙️ レベル2：数値調整

### ミッション2-1：プレイヤーの速さを変える

**難易度：** ⭐⭐ 簡単

**変更ファイル：** `sketch.js` の13行目

```javascript
// 元
let playerSpeed = 7;

// 変更例
let playerSpeed = 10;  // 速くなる
let playerSpeed = 3;   // 遅くなる
```

**実装時間：** 2分

**生徒がつまずく可能性：**
- 数値を文字列 `"10"` で入力してしまう
- セミコロン `;` を忘れる
- どの程度変更すればいいか分からない

**コーチが出すヒント：**
1. 「元の値は 7 です。10 か 5 に変えてみて」
2. 「実際にゲームをプレイして、動きを確認してみて」
3. 「速すぎたら、また調整すればいいんですよ」

**実装のコツ：**
生徒に「試行錯誤」を促す。

- 最初は 10 に変更
- ゲームをプレイ
- 「速すぎたから 8 に変更」
- またプレイ
- 「ちょうどいい」

このプロセスが大事です。

**代替案（完成できなかった場合）：**
選択肢を提示：

```javascript
// 遅い
let playerSpeed = 3;

// ふつう
let playerSpeed = 7;

// 速い
let playerSpeed = 12;
```

### ミッション2-4：遊びやすい難易度に調整する

**難易度：** ⭐⭐⭐ やや難しい（複数要素の組み合わせ）

**変更ファイル：** `sketch.js` の11、12、13行目の複数

```javascript
// 元（デフォルト）
let playerSize = 40;
let enemySize = 35;
let playerSpeed = 7;

// 例1：難しくしたい
let playerSize = 60;   // プレイヤーを大きく（当たりやすく、難しい）
let enemySize = 50;    // 敵を大きく
let playerSpeed = 5;   // プレイヤーを遅く

// 例2：簡単にしたい
let playerSize = 20;   // プレイヤーを小さく（当たりにくく、簡単）
let enemySize = 20;    // 敵を小さく
let playerSpeed = 10;  // プレイヤーを速く
```

**実装時間：** 5分

**生徒がつまずく可能性：**
- 複数の値を同時に変更するので、どれを変更すればいいか分からない
- 「遊びやすい」の定義が曖昧

**コーチが出すヒント：**
1. 「ゲームが難しすぎたら、プレイヤーを小さくしてみて」
2. 「敵も小さくしたり、プレイヤーを速くしたりして、自分にちょうどいい難易度を見つけてみて」
3. 「複数の値を組み合わせて、自分にちょうどいい難易度を作ってみて」

**実装のコツ：**
生徒が複数の値を試行錯誤できるようにサポート。

**代替案（完成できなかった場合）：**
テンプレートを提示：

```javascript
// ★簡単モード

let playerSpeed = 10;

// ★ふつう（デフォルト）
let playerSize = 40;
let enemySize = 35;
let playerSpeed = 7;

// ★難しいモード
let playerSize = 20;
let enemySize = 50;
let playerSpeed = 5;
```

## 🔧 レベル3：難易度ロジックの変更

### ミッション3-1：難易度ごとの敵の速さを変える

**難易度：** ⭐⭐⭐ やや難しい（複数箇所の編集）

**変更ファイル：** `sketch.js` の68〜83行目（`startGame()` 関数内）

```javascript
function startGame(level) {
  if (level === 1) {
    difficultyName = "かんたん";
    enemySpeed = 4;    // ← ここを変更
    enemyCount = 1;
    clearTime = 30;
  } else if (level === 2) {
    difficultyName = "ふつう";
    enemySpeed = 6;    // ← ここを変更
    enemyCount = 2;
    clearTime = 45;
  } else {
    difficultyName = "むずかしい";
    enemySpeed = 8;    // ← ここを変更
    enemyCount = 3;
    clearTime = 60;
  }
  // ...
}
```

**変更例：**

```javascript
// 敵が速くなるように調整
if (level === 1) {
  enemySpeed = 5;   // 元の 4 から 5 に
} else if (level === 2) {
  enemySpeed = 7;   // 元の 6 から 7 に
} else {
  enemySpeed = 9;   // 元の 8 から 9 に
}
```

**実装時間：** 5分

**生徒がつまずく可能性：**
- `if` 文の構造が複雑に見える
- どこを変更すればいいか分からない
- 3つの場所すべてを変更する必要があることに気づかない

**コーチが出すヒント：**
1. 「難易度『かんたん』の敵の速さは、68行目の `enemySpeed = 4` で決まります」
2. 「3つの難易度すべてを同じルールで変更してね」
3. 「『ふつう』は『かんたん』より速く、『むずかしい』が一番速いようにしましょう」

**実装のコツ：**
コーチが、変更すべき3行をハイライトして示す。

生徒に直接変更させず、まずコードを読ませてから変更させる。

**代替案（完成できなかった場合）：**
虫食いコード形式で提供：

```javascript
function startGame(level) {
  if (level === 1) {
    enemySpeed = ____;   // ここに好きな数字を入れてね
  } else if (level === 2) {
    enemySpeed = ____;   // ふつうは、かんたんより大きい数字
  } else {
    enemySpeed = ____;   // むずかしいが一番大きい数字
  }
}
```

## 🛠️ コーチが用意すべきもの

### 資料
- ミッション説明書（プリント）
- 各ミッションの完成例（スクリーンショット）
- よくあるエラーと対応方法のリスト

### サポート方法
1. **進捗確認** — 5分ごとに生徒の画面を確認
2. **つまずき対応** — 早期に手を挙げさせる
3. **試行錯誤を促す** — 答えをすぐに教えない
4. **成功体験** — 完成したら褒める

### よくあるエラーと対応

| エラー | 原因 | 対応 |
|--------|------|------|
| 色が変わらない | 保存忘れ・更新忘れ | 「Ctrl+S で保存してから、F5 で更新してね」 |
| スペルエラー | 色名の入力ミス | 色名リストを提示 |
| セミコロン忘れ | 文法エラー | 「行の最後に `;` がありますか」 |
| `if` 文の構造が分からない | 複雑に見える | 「3つの難易度ごとに、値が異なるんです」 |
| 複数の値をどう組み合わせればいいか分からない | 試行錯誤の方法が分からない | 「1つずつ試してみましょう」 |

>
> 色やタイトルを好きなものに変えて、「自分だけのゲーム」を作ってみましょう。

### レベル2を説明するとき
> ゲームが難しすぎたり簡単すぎたりしたら、プレイヤーの大きさや速度を調整できます。
>
> 複数の値を組み合わせることで、自分好みの難易度が作れます。

### レベル3を説明するとき
> 難易度ごとに敵の数や速度を変えたり、制限時間を変更したりすることで、より深いカスタマイズができます。
>
> これは、プログラミングの「条件分岐」という考え方を使っています。

### テーマ作成を説明するとき
> ゲーム全体の色、大きさ、速度、タイトルを組み合わせて、自分だけの世界観を作ってみましょう。
>
> プログラミングの楽しさは、「自分のアイデアが実現できる」ことです。
