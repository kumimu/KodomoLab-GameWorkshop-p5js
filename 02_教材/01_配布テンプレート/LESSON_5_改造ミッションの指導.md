# レッスン5：改造ミッションの指導

## 当日の使い方

対応する時間帯は、**32～35分「ゲーム本体で最初の改造」と35～55分「応用課題の実装」**です。授業で画面共有する中心資料は[生徒用テキスト](../../00_当日用資料/01_生徒/02_ワークショップテキスト.html)です。このLESSONは、仕組みを詳しく読みたい人やコーチの参考用で、全編を投影して読む時間は設けません。

10～25分はpractice.jsで数値・色・タイトル・変数を体験し、25～32分は生徒テキストの「ゲーム全体の地図」、32～35分はゲーム本体の色変更を扱います。必要なときだけ、この資料の該当箇所を補足に使います。

「現在のコード」と示す例はシンプル版sketch.jsの対応する関数です。「抜粋」「考え方の例」は説明用で、そのまま本体へ追加するコードではありません。改造では既存の値を変更し、応用機能は[当日用の課題ページ](../../00_当日用資料/01_生徒/応用課題/00_課題の選び方.html)からコピーします。

変更例で複数の値を並べている場合は候補の比較です。使う値を1つ選び、既存の設定行を書き換えます。新しい設定行を末尾へ追加しません。

## 🎯 学習目標

ワークショップで参加者が行う改造ミッションを、難易度ごとに分析する。

- 各ミッションの内容と実装方法
- 難易度別のサポート方法
- よくあるエラーと対応
- コーチが生徒を導くためのヒント
- 時間内に完成させるための工夫

## 🎨 レベル1：基本の色・テーマ変更

### ミッション1-1：プレイヤーの色を変える

**難易度：** ⭐ 最も簡単

**変更ファイル：** `sketch.js` の対応箇所（関数名で検索）

```javascript
// 元
let playerColor = "cyan";

// 変更例
playerColor = "lime";
playerColor = "#FF6B9D";
```

**実装時間：** 1分

**生徒がつまずく可能性：**
- 色名のスペルが違う（`"gren"`ではなく`"green"`など）
- セミコロン `;` を忘れる
- 保存忘れ、またはブラウザの更新忘れ

**コーチが出すヒント：**
1. 「p5.jsの色名で、好きな色を探してみて」
2. 「'lime', 'yellow', 'pink' などの色名が使えます」
3. 「セミコロンをつけて、保存してから F5 で更新してね」
4. 「カラーピッカーを使えば、好きな色の16進数が分かりますよ」

**コーチが教える前に確認すること：**
- 生徒が、CUSTOM AREA のどこを変更するのか理解しているか
- 正しい色名を入力しているか
- 保存と更新のステップを忘れていないか

**代替案（完成できなかった場合）：**
色名リストを提示して、その中から選ばせる：

```javascript
// 用意した色名
"cyan"     // シアン（水色）
"lime"     // ライム（黄緑）
"yellow"   // 黄
"orange"   // オレンジ
"pink"     // ピンク
"purple"   // 紫
```

## ⚙️ レベル2：数値調整

### ミッション2-1：プレイヤーの速さを変える

**難易度：** ⭐⭐ 簡単

**変更ファイル：** `sketch.js` の対応箇所（関数名で検索）

```javascript
// 元
let playerSpeed = 7;

// 変更例
playerSpeed = 10;  // 速くなる
playerSpeed = 3;   // 遅くなる
```

**実装時間：** 2分

**生徒がつまずく可能性：**
- 数値を文字列 `"10"` で入力してしまう
- セミコロン `;` を忘れる
- どの程度変更すればいいか分からない

**コーチが出すヒント：**
1. 「元の値は 7 です。10 か 5 に変えてみて」
2. 「実際にゲームをプレイして、動きを確認してみて」
3. 「速すぎたら、また調整すればいいんですよ」

**実装のコツ：**
生徒に「試行錯誤」を促す。

- 最初は 10 に変更
- ゲームをプレイ
- 「速すぎたから 8 に変更」
- またプレイ
- 「ちょうどいい」

このプロセスが大事です。

**代替案（完成できなかった場合）：**
選択肢を提示：

```javascript
// 遅い
let playerSpeed = 3;

// ふつう
playerSpeed = 7;

// 速い
playerSpeed = 12;
```

**難易度：** ⭐⭐ 簡単

**変更ファイル：** `sketch.js` の対応箇所（関数名で検索）

**実装時間：** 2分

**生徒がつまずく可能性：** ミッション2-1と同じ

**コーチが出すヒント：**
1. 「大きくなると、当たりやすくなります」
2. 「小さくなると、避けやすくなります」
3. 「自分にちょうどいい大きさを見つけてみて」

**実装のコツ：**
難易度と直結している。

- `playerSize` を大きくする = 避けやすい = 簡単
- `playerSize` を小さくする = 避けにくい = 難しい

### ミッション2-4：遊びやすい難易度に調整する

**難易度：** ⭐⭐⭐ やや難しい（複数要素の組み合わせ）

**変更ファイル：** `sketch.js` の対応箇所（関数名で検索）の複数

```javascript
// 元（デフォルト）
let playerSize = 40;
let enemySize = 35;
let playerSpeed = 7;

// 例1：難しくしたい
playerSize = 60;   // プレイヤーを大きく（当たりやすく、難しい）
enemySize = 50;    // 敵を大きく
playerSpeed = 5;   // プレイヤーを遅く

// 例2：簡単にしたい
playerSize = 20;   // プレイヤーを小さく（当たりにくく、簡単）
enemySize = 20;    // 敵を小さく
playerSpeed = 10;  // プレイヤーを速く
```

**実装時間：** 5分

**生徒がつまずく可能性：**
- 複数の値を同時に変更するので、どれを変更すればいいか分からない
- 「遊びやすい」の定義が曖昧

**コーチが出すヒント：**
1. 「ゲームが難しすぎたら、プレイヤーを小さくしてみて」
2. 「敵も小さくしたり、プレイヤーを速くしたりして、自分にちょうどいい難易度を見つけてみて」
3. 「複数の値を組み合わせて、自分にちょうどいい難易度を作ってみて」

**実装のコツ：**
生徒が複数の値を試行錯誤できるようにサポート。

**代替案（完成できなかった場合）：**
テンプレートを提示：

```javascript
// ★簡単モード
let playerSize = 60;
let enemySize = 20;
let playerSpeed = 10;

// ★ふつう（デフォルト）
playerSize = 40;
enemySize = 35;
playerSpeed = 7;

// ★難しいモード
playerSize = 20;
enemySize = 50;
playerSpeed = 5;
```

- CUSTOM AREA 内の複数の値を組み合わせる

- 時間内に完成する（5〜10分）

## 🔧 レベル3：難易度ロジックの変更

### ミッション3-1：難易度ごとの敵の速さを変える

**難易度：** ⭐⭐⭐ やや難しい（複数箇所の編集）

**変更ファイル：** `sketch.js` の対応箇所（関数名で検索）（`startGame()` 関数内）

```javascript
// 【役割】選んだ難易度でゲームを初期化して開始します。
function startGame(level) {
  if (level === 1) {
    difficultyName = "かんたん";
    enemySpeed = 4;    // ← ここを変更
    enemyCount = 1;
    clearTime = 30;
  } else if (level === 2) {
    difficultyName = "ふつう";
    enemySpeed = 6;    // ← ここを変更
    enemyCount = 2;
    clearTime = 45;
  } else {
    difficultyName = "むずかしい";
    enemySpeed = 8;    // ← ここを変更
    enemyCount = 3;
    clearTime = 60;
  }
  // ...
}
```

**変更例：**

```javascript
// 敵が速くなるように調整
if (level === 1) {
  enemySpeed = 5;   // 元の 4 から 5 に
} else if (level === 2) {
  enemySpeed = 7;   // 元の 6 から 7 に
} else {
  enemySpeed = 9;   // 元の 8 から 9 に
}
```

**実装時間：** 5分

**生徒がつまずく可能性：**
- `if` 文の構造が複雑に見える
- どこを変更すればいいか分からない
- 3つの場所すべてを変更する必要があることに気づかない

**コーチが出すヒント：**
1. 「難易度『かんたん』の敵の速さは、68行目の `enemySpeed = 4` で決まります」
2. 「3つの難易度すべてを同じルールで変更してね」
3. 「『ふつう』は『かんたん』より速く、『むずかしい』が一番速いようにしましょう」

**実装のコツ：**
コーチが、変更すべき3行をハイライトして示す。

生徒に直接変更させず、まずコードを読ませてから変更させる。

**代替案（完成できなかった場合）：**
虫食いコード形式で提供：

```javascript
// 【役割】選んだ難易度でゲームを初期化して開始します。
function startGame(level) {
  if (level === 1) {
    enemySpeed = ____;   // ここに好きな数字を入れてね
  } else if (level === 2) {
    enemySpeed = ____;   // ふつうは、かんたんより大きい数字
  } else {
    enemySpeed = ____;   // むずかしいが一番大きい数字
  }
}
```

### ミッション3-4：自分だけのテーマを考える

**難易度：** ⭐⭐⭐⭐ 難しい（総合的な改造）

**変更ファイル：** `sketch.js` の対応箇所（関数名で検索）（CUSTOM AREA全体）

```javascript
// 元
let playerColor = "cyan";
let enemyColor = "red";
let backgroundColor = "black";
let playerSize = 40;
let enemySize = 35;
let playerSpeed = 7;
let gameTitle = "隕石をよけろ！";

// 例：「宇宙戦闘」テーマ
playerColor = "#00FF00";      // ネオン緑（自機）
enemyColor = "#FF0000";       // 赤（敵機）
backgroundColor = "#000033";  // 濃い青（宇宙）
playerSize = 50;              // 大きい戦闘機（当たりやすく、難しい）
enemySize = 40;               // 大きい敵
playerSpeed = 9;              // 速い戦闘
gameTitle = "宇宙戦闘 - エイリアンを倒せ！";
```

**実装時間：** 10分

**生徒がつまずく可能性：**
- テーマが思いつかない
- 複数の要素をバランスよく調整できない
- 色やサイズの組み合わせがちぐはぐになる

**コーチが出すヒント：**
1. 「好きな世界観を思い浮かべて。例えば、『宇宙』『海底』『魔法の森』など」
2. 「色、大きさ、速度、タイトルを、その世界観に合わせて変更してみて」
3. 「実際にゲームをプレイしながら、バランスを整えましょう」

**実装のコツ：**
生徒に「ゲーム制作の自由度」を実感させる。

**テーマの例：**
- 「宇宙戦闘」— 派手な色、速い敵、シアンと赤
- 「深海」— 暗い青と緑、ゆっくりとした敵
- 「ジャングル」— 緑と茶色、大きな敵
- 「雪の世界」— 白と水色、遅い敵

**代替案（完成できなかった場合）：**
テーマを決めて、そこからスタート：

```javascript
// 火星ミッションテーマ
let playerColor = "#FFCC00";      // 黄色
let enemyColor = "#FF6600";       // オレンジ
let backgroundColor = "#330000";  // 暗い赤
let gameTitle = "火星探査 - 隕石を避けろ！";
```

## 📋 レベル3の特徴

**「ゲームロジックと複合設定」**

- CUSTOM AREA だけでなく、関数の中身も変更する必要がある
- 複数の場所を同じルールで変更する必要がある
- 試行錯誤の余地が大きい
- 時間内に完成する可能性は中程度（10〜15分）
- 達成感が非常に高い

**推奨：** レベル2までが完成した生徒が、さらに改造を深める場合に選ぶ

## 🛠️ コーチが用意すべきもの

### 資料
- 最新の生徒用テキストと、当日用の応用課題ページ
- コーチ用の虫食い課題の解答と確認
- よくあるエラーと対応方法のリスト

### サポート方法
1. **進捗確認** — 5分ごとに生徒の画面を確認
2. **つまずき対応** — 早期に手を挙げさせる
3. **試行錯誤を促す** — 答えをすぐに教えない
4. **成功体験** — 完成したら褒める

### よくあるエラーと対応

| エラー | 原因 | 対応 |
|--------|------|------|
| 色が変わらない | 保存忘れ・更新忘れ | 「Ctrl+S で保存してから、F5 で更新してね」 |
| スペルエラー | 色名の入力ミス | 色名リストを提示 |
| セミコロン忘れ | 文法エラー | 「行の最後に `;` がありますか」 |
| `if` 文の構造が分からない | 複雑に見える | 「3つの難易度ごとに、値が異なるんです」 |
| 複数の値をどう組み合わせればいいか分からない | 試行錯誤の方法が分からない | 「1つずつ試してみましょう」 |

## 🎓 中学生への説明例（講師向け）

### レベル1を説明するとき
> CUSTOM AREA の値を変えるだけで、ゲームが大きく変わります。
>
> 色やタイトルを好きなものに変えて、「自分だけのゲーム」を作ってみましょう。

### レベル2を説明するとき
> ゲームが難しすぎたり簡単すぎたりしたら、プレイヤーの大きさや速度を調整できます。
>
> 複数の値を組み合わせることで、自分好みの難易度が作れます。

### レベル3を説明するとき
> 難易度ごとに敵の数や速度を変えたり、制限時間を変更したりすることで、より深いカスタマイズができます。
>
> これは、プログラミングの「条件分岐」という考え方を使っています。

### テーマ作成を説明するとき
> ゲーム全体の色、大きさ、速度、タイトルを組み合わせて、自分だけの世界観を作ってみましょう。
>
> プログラミングの楽しさは、「自分のアイデアが実現できる」ことです。

## 📝 進捗の確認（コーチ向け）

記録は生徒用の[改造・発見ノート](../../00_当日用資料/01_生徒/03_改造と発見のノート.html)を使います。コーチは次を目印に支援します。
