🎮 プレイヤーが「移動して見える」仕組み

レッスン1で学んだとおり、ゲームは毎フレーム（1秒間に約60回を目安に）、背景を消して新しい画像を描き直しています。

プレイヤーの移動も、これと同じです。

毎フレーム、プレイヤーの位置（playerX）が少しずつ変わります。

だから、プレイヤーが移動しているように「見える」のです。

フレーム1：playerX = 300
フレーム2：playerX = 293  (左矢印を押した)  ← 300 - 7 = 293
フレーム3：playerX = 286  ← 293 - 7 = 286
フレーム4：playerX = 279  ← 286 - 7 = 279
フレーム5：playerX = 272  ← 279 - 7 = 272（連続して変わるから、移動に見える）

📍 座標システムの確認

ゲーム画面の座標は、左上を基準にしています。

  • 左端 = X座標 0
  • 右端 = X座標 600
  • 上端 = Y座標 0
  • 下端 = Y座標 400

プレイヤーが画面中央にいれば、playerX はおよそ 300 です。

⌨️ キー入力の受け取り方

movePlayer() 関数

sketch.js の対応箇所（関数名で検索）：

// 【役割】キーに応じて自機を動かします。
function movePlayer() {
  if (keyIsDown(LEFT_ARROW)) {
    playerX -= playerSpeed;
  }
  if (keyIsDown(RIGHT_ARROW)) {
    playerX += playerSpeed;
  }

  playerX = constrain(playerX, playerSize / 2, width - playerSize / 2);
}

keyIsDown() 関数とは

keyIsDown(LEFT_ARROW) は、p5.jsが提供する関数です。

「この瞬間、LEFT_ARROW（左矢印キー）が押されていますか？」と確認します。

  • 押されている → true（真）
  • 押されていない → false（偽）

左矢印キーが押された場合

if (keyIsDown(LEFT_ARROW)) {
  playerX -= playerSpeed;
}

このコードを読む：

  1. if (...) — もし〜なら
  2. keyIsDown(LEFT_ARROW) — 左矢印キーが押されていたら
  3. playerX -= playerSpeed — playerX から playerSpeed を引く（左に移動）

例： playerX = 300、playerSpeed = 7 の場合

playerX -= 7;  // playerX = 300 - 7 = 293

プレイヤーが左に7ピクセル移動します。

右矢印キーが押された場合

if (keyIsDown(RIGHT_ARROW)) {
  playerX += playerSpeed;
}

このコードを読む：

  1. if (...) — もし〜なら
  2. keyIsDown(RIGHT_ARROW) — 右矢印キーが押されていたら
  3. playerX += playerSpeed — playerX に playerSpeed を足す（右に移動）

例： playerX = 300、playerSpeed = 7 の場合

playerX += 7;  // playerX = 300 + 7 = 307

プレイヤーが右に7ピクセル移動します。

🔄 毎フレーム何が起こるのか

レッスン1で学んだゲームループを思い出してください。 次は移動と描画だけに絞った説明用の抜粋です。開始・終了画面やその他の処理を省略しているので、sketch.jsにある関数全体とは区別して読みます。

// 【役割】プレイ中の描画を呼ぶ部分だけを示す、説明用の抜粋です。
function draw() {
  background(backgroundColor);
  if (gameState === "play") {
    playGame();
  }
}

// 【役割】移動してから描く順序を示します。他の処理は省略しています。
function playGame() {
  movePlayer();
  // ゲームのコードでは、この間に追加機能の更新と情報表示があります。
  drawPlayer();
  // 時間判定、追加の描画、敵の処理はここでは省略しています。
}

毎フレーム、以下の順で起こります：

  1. 背景を描き直す（前フレームの画像を消す）
  2. playGame() が実行される
  3. movePlayer() で、キー入力に基づいて playerX を更新する
  4. drawPlayer() で、新しい位置にプレイヤーを描く
  5. 敵も同様に移動・描画される

この処理を毎フレーム繰り返します。

🛑 constrain() 関数で画面の端を制御

なぜ constrain() が必要なのか

もし constrain() がなければ、こうなります：

// 【役割】キーに応じて自機を動かします。
function movePlayer() {
  if (keyIsDown(LEFT_ARROW)) {
    playerX -= playerSpeed;
  }
  if (keyIsDown(RIGHT_ARROW)) {
    playerX += playerSpeed;
  }

  playerX = constrain(playerX, playerSize / 2, width - playerSize / 2);
}

プレイヤーが左矢印を押し続けると、playerX はどんどん小さくなります。

playerX = 300
playerX = 293
playerX = 286
playerX = 279
playerX = 50
playerX = -20    ← 画面の左側の外へ出てしまう！
playerX = -100
...

マイナスの座標に描かれたプレイヤーは、画面に見えません。

これは、ゲームとして不自然です。

constrain() 関数の役割

playerX = constrain(
  playerX,
  playerSize / 2,
  width - playerSize / 2
);

constrain() は、値を指定の範囲内に制限します。

引数（中身）は3つ：

引数 意味
第1引数：playerX 制限したい値
第2引数：playerSize / 2 最小値
第3引数：width - playerSize / 2 最大値

つまり：

constrain(playerX, 左の端, 右の端);

📐 具体的な計算

画面のサイズ

width = 600   // 画面の幅
height = 400  // 画面の高さ

プレイヤーのサイズ

playerSize = 40

constrain() の範囲

playerX = constrain(
  playerX,
  playerSize / 2,        // 40 / 2 = 20
  width - playerSize / 2 // 600 - 20 = 580
);

つまり、playerX は 20〜580 の範囲に制限されます。

なぜ playerSize / 2 なのか

プレイヤーは三角形で、中心が (playerX, playerY) です。

三角形の横幅の半分は playerSize / 2 なので、

  • プレイヤーの左端 = playerX - playerSize / 2 = 20 - 20 = 0（画面の左端）
  • プレイヤーの右端 = playerX + playerSize / 2 = 580 + 20 = 600（画面の右端）

プレイヤー全体が画面内に収まるようにしています。

📊 移動の流れ（完全版）

状態1：初期状態

playerX = 300      // 画面中央
playerSize = 40
playerSpeed = 7

状態2：左矢印キーを3フレーム押し続けた場合

フレーム1：

if (keyIsDown(LEFT_ARROW)) {
  playerX -= 7; // playerX = 300 - 7 = 293
}
playerX = constrain(293, 20, 580);        // 293は範囲内なので変わらない
// playerX = 293

フレーム2：

if (keyIsDown(LEFT_ARROW)) {
  playerX -= 7; // playerX = 293 - 7 = 286
}
playerX = constrain(286, 20, 580);        // 286は範囲内
// playerX = 286

フレーム3：

if (keyIsDown(LEFT_ARROW)) {
  playerX -= 7; // playerX = 286 - 7 = 279
}
playerX = constrain(279, 20, 580);        // 279は範囲内
// playerX = 279

結果：プレイヤーは3フレーム × 7ピクセル = 21ピクセル左に移動しました。

状態3：画面の端に達した場合

プレイヤーが左端に近づいて、playerX = 25 の状態で、さらに左矢印を押した場合：

if (keyIsDown(LEFT_ARROW)) {
  playerX -= 7; // playerX = 25 - 7 = 18
}
playerX = constrain(18, 20, 580);         // 18 < 20 なので、20に制限される
// playerX = 20（画面の端で止まる）

次のフレーム：

if (keyIsDown(LEFT_ARROW)) {
  playerX -= 7; // playerX = 20 - 7 = 13
}
playerX = constrain(13, 20, 580);         // 13 < 20 なので、20に制限
// playerX = 20（そのまま）

プレイヤーが左端を超えません。

⏱️ 移動速度の計算

playerSpeed の意味

playerSpeed = 7 は、「左右どちらかのキーを押している間、1フレームあたり最大7ピクセル移動」を意味します。

1秒間の移動距離

ここでは60フレーム/秒と仮定します。実際のフレーム数はPCやブラウザの負荷で変わります。

1秒間の移動距離 = playerSpeed × フレームレート
                = 7 × 60
                = 420ピクセル/秒

画面の端に達しなければ、左矢印キーを1秒間押し続けると420ピクセル左へ移動します。

画面の左端から右端までの移動

画面の幅が600ピクセル、プレイヤーの幅が40ピクセルのとき、プレイヤーの中心は左端で20、右端で580です。中心の移動距離は580 − 20 = 560ピクセルです。

速さが7なら、560 ÷ 7 = 80フレームかかります。60フレーム/秒なら、80 ÷ 60 ≈ 1.33秒です。

playerSpeed を変更した場合

例：playerSpeed = 10 に変更

1秒間の移動距離 = 10 × 60 = 600ピクセル/秒
左端から右端まで = 56フレーム ÷ 60 ≈ 0.93秒

もっと速く移動できます。

例：playerSpeed = 3 に変更

1秒間の移動距離 = 3 × 60 = 180ピクセル/秒
左端から右端まで = 187フレーム ÷ 60 ≈ 3.12秒

560 ÷ 3 は約186.67なので、187フレーム目に右端へ着きます。

📝 重要な用語のまとめ

用語 意味 このゲームでの例
キー入力 ユーザーがキーボードで何かを押すこと 左矢印キーを押す
keyIsDown() 特定のキーが押されているか確認する関数 keyIsDown(LEFT_ARROW)
座標更新 プレイヤーの位置（X座標）を変える playerX += 7
加算代入 += で値を足す playerX += 7 は playerX = playerX + 7 と同じ
減算代入 -= で値を引く playerX -= 7 は playerX = playerX - 7 と同じ
constrain() 値を指定の範囲内に制限する関数 プレイヤーを画面内に留める
フレームレート 1秒間のフレーム数 60 FPS = 1秒間に60フレーム

📌 コードの読み方（演習）

演習1：このコードは何をしている？

if (keyIsDown(RIGHT_ARROW)) {
  playerX += playerSpeed;
}

答え： 右矢印キーが押されていれば、プレイヤーを右に playerSpeed ピクセル移動させる。

演習2：constrain() の役割は？

playerX = constrain(playerX, playerSize / 2, width - playerSize / 2);

答え： playerX を、20〜580 の範囲に制限する。これによって、プレイヤーが画面外に出ないようにする。

演習3：もし constrain() がなかったら？

// constrain() がない場合
if (keyIsDown(LEFT_ARROW)) {
  playerX -= playerSpeed;
}
if (keyIsDown(RIGHT_ARROW)) {
  playerX += playerSpeed;
}

答え： プレイヤーが画面外に移動してしまい、見えなくなる可能性がある。

playerSpeed = 10、フレームレート60 FPS、画面の幅600ピクセル、プレイヤーの幅40ピクセルのとき、プレイヤーが画面の左端から右端に到達するまでにかかる時間は何秒ですか？
